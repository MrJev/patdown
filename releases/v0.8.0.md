## Scoped lint without shell gymnastics

`--files` and `--files-from` accept files, directories, or globs. Directories expand (same skips as rule globs: `.git`, `dist`, `node_modules`, …). `--files-from -` reads newline-separated paths from stdin. Missing `--files` paths fail. Before judgments:

```
patdown: linting 12 files against 6 rules
```

`--verbose` streams each rule box as files are judged: open with the planned count, rows as they finish, close with the fail tally. Quiet mode stays one `PASS`/`FAIL` line per judgment.

```
pnpm -w patdown -- --files src --verbose
git ls-files 'src' | pnpm -w patdown -- --files-from -
```

## GitHub annotation levels

FAIL annotations are no longer hard-coded as `::error`. Levels: `error`, `warning`, `notice`. Display only; exit status still follows the cutoff.

Most specific wins: per-rule `github-annotation:` → frontmatter `github-annotation:` → `--github-annotation` / package.json `patdown.githubAnnotation` → `error`.

```
---
include:
  - ./node_modules/@patdown/packs/typescript
github-annotation: warning
---

# No title case
globs: **/*.md
github-annotation: error

Markdown headings must use sentence case.
```

## Composite GitHub Action

Pin the repo instead of copy-pasting yaml:

```yaml
- uses: actions/checkout@v4
  with:
    fetch-depth: 0

- uses: tyler-dot-earth/patdown@v0.8.0
  with:
    github-annotation: warning
  env:
    TYPESAFE_API_KEY: ${{ secrets.TYPESAFE_API_KEY }}
```

The action lists changed files under `RUNNER_TEMP` (paths relative to `working-directory`) and runs `npx patdown@0.8.0`. Custom report shapes stay an embed of `runPatdownCli` with your own `PatdownOutput` layer, not an action input. See [GitHub Actions](../docs/github-actions.md).

## Provider-neutral judging

- Introduces `PatdownJudge`, a swappable Effect service returning `yesProbability`. TypeSafe/Jev remains the default backend behind `TypeSafeJudgeLive`.
- Keeps the decision cutoff in patdown: probabilities strictly above 0.85 count as yes. In lint, yes means a violation.
- Validates probabilities as finite numbers between 0 and 1.
- Allows embedded callers to pass a judge layer as the third argument to `runPatdownCli`, independently of the rules adapter.
- Documents the planned migration to Effect's upcoming `Decision` and `DecisionModel` modules. This release does not depend on those unreleased APIs.

## CLI migration

The direct-question flags have changed. There are no compatibility aliases:

```sh
# Before
pnpm -w patdown -- ask --noul "Is this urgent?" --state "ASAP"

# Now
pnpm -w patdown -- ask "Is this urgent?" --input-text "ASAP"
```

Default answers are now just `yes` or `no`. Add `--verbose` to see estimated P(yes) and the cutoff. Lint output uses `PASS path: rule` / `FAIL path: rule`, with probability details also opt-in. Scripts parsing the old output need updating.

`ask` reports a judgment without failing on yes. Lint still exits 1 for violations.

## Piped input

`--stdin` reads UTF-8 text through EOF, preserving newlines. It cannot be combined with `--input-text`. With neither flag, input is an empty string.

After building the checkout:

```sh
git diff --cached | node apps/patdown/dist/patdown-cli-bin.js ask "Does this diff introduce debugging statements?" --stdin
```

Piped content goes to the configured judge. Do not send secrets.

## Embedded API changes

Custom judges implement `PatdownJudge.ask(question, inputText)` and return `{ yesProbability }` or fail with `PatdownJudgeFailed`. The CLI no longer consumes `JevSystemOne` directly.

Custom output layers now implement `writeAnswer` and `writeLintResult` instead of `writeNoulDecision` and `writeLintLine`. The old provider-specific threshold helpers were removed; use `patdownJudgmentIsYes` and `patdownYesThreshold` from the CLI library.

See the checked-in [judge guide](https://github.com/tyler-dot-earth/patdown/blob/v0.2.0/docs/judge-providers.md) and [rule source adapter guide](https://github.com/tyler-dot-earth/patdown/blob/v0.2.0/docs/rule-source-adapters.md).

## Project changes

- Adds the Zero-Clause BSD license and updates package metadata. Vendored third-party licenses remain intact.
- Adds versioned release notes with frontmatter under `releases/`; GitHub release bodies use these files.
- Adds tests for neutral judges, output, input selection, and pipe handling.

## Distribution

Still a source-only GitHub release. No npm publication or standalone bundle. Requires Node.js >=24.18.0 and matching Effect prerelease versions for custom adapters. The `pnpm -w patdown` wrapper builds automatically but executes from `apps/patdown`; invoke the built executable from your target directory when cwd matters.

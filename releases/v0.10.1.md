## Claude plugin resolve and cache version

`@patdown/claude` now keeps `plugin.json` / marketplace metadata on the same version as the npm package (they were stuck at `0.8.0` through `0.10.0`). The release script bumps those files with the publishable packages.

The PreToolUse hook resolves `patdown` from the project being edited, then loads `@patdown/rules`, `effect`, and `@effect/platform-node` from that package so pnpm's isolated layout still works. Missing project installs deny with an install hint. Missing `AGENTS.PATDOWN.md` skips judging instead of blocking every write.

Install into the project Claude is editing, then refresh the plugin if Claude still shows an old cache path:

```sh
pnpm add -D patdown @patdown/rules
claude --plugin-dir ./node_modules/@patdown/claude
```

See [Claude Code plugin](../docs/claude.md).

## Distribution

Requires Node.js >=22.22.2. Published as `patdown`, `@patdown/rules`, `@patdown/pi`, `@patdown/claude`, and `@patdown/packs`. The same git tag is what consumers pin for the composite action.

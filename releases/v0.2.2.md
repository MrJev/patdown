## Accurate Jev errors

The TypeSafe/Jev adapter no longer collapses non-success HTTP responses into `System One request failed`.

- Reports HTTP status, validated provider error code, input UTF-8 byte count, and TypeSafe request ID when available.
- Recognizes `max_tokens_exceeded` and recommends reducing or splitting input.
- Distinguishes HTTP 413 payload limits, authentication/access failures, rate/quota limits, server/upstream failures, transport failures, and invalid success responses.
- Preserves HTTP status even when an error body is not JSON. Arbitrary provider prose, HTML, input, and credentials are not printed.
- Adds optional `status`, `providerErrorCode`, and `requestId` fields to `JevRequestFailed` for direct client consumers.

Existing commands, verdicts, cutoff, and exit behavior are unchanged. No truncation, automatic chunking, retries, or new input-size limit was added. Scripts matching the old error text should account for the more specific messages.

## Live size testing

Direct tests against `jev-latest` (resolved to `jev-1.13.0`) accepted a 96,768-byte synthetic diff and rejected 97,536 bytes with HTTP 400 and `max_tokens_exceeded`. A 1,500,000-byte diff received the same rejection, not HTTP 413. A larger low-token control input succeeded, confirming that bytes alone are not a safe cutoff.

These measurements do not establish an exact permanent token limit or Vercel AI Gateway's limits. See [the results and caveats](https://github.com/tyler-dot-earth/patdown/blob/v0.2.2/docs/jev-input-limits.md).

Adds an opt-in, potentially billable synthetic-input probe under `scripts/probe-jev-input-size.mjs`, plus simulated HTTP regression tests. Live API calls are not part of CI.

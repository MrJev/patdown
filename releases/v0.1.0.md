## Rule source adapters

- Adds `--adapter` and package.json `patdown.adapter` discovery. Adapters export a `PatdownRuleSourceLive` Effect Layer and can load other formats or multiple files.
- Resolves package adapters from the consumer project, including ESM import conditions.
- Validates imported services and returned rules; reports invalid configuration instead of silently reverting to markdown.
- Provides FileSystem and Path to scoped adapters and releases resources after loading.
- Keeps adapter discovery out of `ask`, help, and version commands.
- Documents the adapter contract with a multi-file example.

## Embedding and migration

The CLI package entrypoint is now a library. `runPatdownCli` returns an Effect, and consumers can supply their own rule-source layer.

**Executable path changed:** scripts that invoked `apps/patdown/dist/index.js` must use `apps/patdown/dist/patdown-cli-bin.js`. The workspace `pnpm -w patdown` command handles this automatically and builds through Turbo.

The direct-question syntax remains `ask --noul "question" --state "text"` in this release. The friendlier syntax arrives in v0.2.0.

## Other changes

- Confirms that `##` and deeper headings remain part of a rule body. The dogfood rules now use subsections for examples and exceptions.
- Improves adapter-import diagnostics and addresses Effect compiler suggestions.
- Adds Effect-based adapter execution and resource-lifetime tests.

## Distribution

Source-only GitHub release, with no npm publication or standalone bundle. Requires Node.js >=24.18.0. The workspace command still executes from `apps/patdown`.

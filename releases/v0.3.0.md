## Configurable yes cutoff

The default cutoff is still **0.85**. Yes still means estimated P(yes) is strictly above the cutoff. Equality is not yes. `1` is rejected because nothing can exceed it.

Override the run-level cutoff with:

```sh
pnpm -w patdown -- --yes-threshold 0.9
pnpm -w patdown -- ask "Is this urgent?" --input-text "ASAP" --yes-threshold 0.7 --verbose
```

or package.json:

```json
{
	"patdown": {
		"yesThreshold": 0.9
	}
}
```

`--yes-threshold` wins over package.json. Discovery still walks from cwd; a nearer package.json without `yesThreshold` does not hide a parent that has one. Invalid JSON still fails adapter discovery for lint/`rules`. `ask` ignores broken adapter JSON when reading only a cutoff.

## Per-rule cutoffs

Markdown rules may set their own cutoff immediately under the heading, in either order with `globs:`:

```md
# No title case

globs: **/*.md
yes-threshold: 0.9
```

A second `yes-threshold:` line is an error. A later line in the body is ordinary text. Adapters may supply `patdownRuleYesThreshold` on a rule; omit it to use the run-level cutoff.

`--verbose` now prints the cutoff that was actually applied. Custom output layers receive `yesThreshold` on each lint result. `writeAnswer` accepts an optional third argument for the cutoff used to decide yes/no.

## Embedded API

`patdownJudgmentIsYes(judgment, yesThreshold?)` now takes an optional cutoff. `patdownYesThreshold` remains the default 0.85. Custom output implementations should pass a cutoff into `writeAnswer` and include `yesThreshold` on `PatdownLintResult`.

## Distribution

Source-only GitHub release; no npm publication or standalone bundle. Requires Node.js >=24.18.0 on `main`. Node 22.22.2 support remains on the `node22-compat` branch.

## Pi write steering

[`@patdown/pi`](../packages/patdown-pi/) is a Pi package that judges `write` and `edit` against the same fuzzy rules as the CLI, before those tools hit disk (or after, if you ask).

```sh
pi install npm:@patdown/pi
```

Default is `block` on `tool_call`. `/patdown steer` lets the write land, then queues a follow-up. `/patdown warn` is TUI-only. `/patdown before|after|both` picks the hook; `block` always uses `before`. `/patdown ` (trailing space) lists those subcommands.

Judge errors are never converted to a pass. Missing `AGENTS.PATDOWN.md` turns steering off. Bash is ignored. See [Pi write steering](../docs/pi.md).

## Packs on npm

Optional rule bundles publish as [`@patdown/packs`](../packages/patdown-packs/). `@patdown/rules` remains the parser library.

```sh
pnpm add -D @patdown/packs
npx patdown --rules ./node_modules/@patdown/packs/typescript
npx patdown --rules ./node_modules/@patdown/packs/typescript/do-not-launder-types-with-casts.md
```

Subpaths:

- `@patdown/packs/typescript`
- `@patdown/packs/effect`
- `@patdown/packs/anti-slop`
- `@patdown/packs/<pack>/<rule>.md`

Source of truth in the repo is still `packs/`. The npm package copies that tree at pack time.

## Distribution

Requires Node.js >=22.22.2. Published as `patdown`, `@patdown/rules`, `@patdown/jev`, `@patdown/pi`, and `@patdown/packs`.
